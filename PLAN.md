2026-05-20: Schema-bundle loader rewritten to match the 2026-05-14 design-doc shape it had drifted from. `schema.sql` previously held `PRAGMA journal_mode = WAL` at the top *and* `PRAGMA user_version = 1` near the top, and `schema::ensure_schema` ran the whole file via `execute_batch` with no surrounding transaction. A mid-bundle CREATE failure would leave `user_version = 1` paired with a partial schema, and the next open would short-circuit on the `1 => Ok(())` arm of the version gate without ever re-running the bundle. Fix: split the two ambient PRAGMAs out of `schema.sql`. `schema::ensure_schema` now runs `PRAGMA journal_mode = WAL` against the bare connection first (SQLite forbids journal-mode changes inside a transaction), then opens a `conn.transaction()` and runs `execute_batch(SCHEMA_SQL)` followed by `execute_batch("PRAGMA user_version = 1")`, then commits. Mid-bundle failure rolls the DDL *and* the version stamp back atomically; the next open sees `user_version = 0` and re-runs the (non-`IF NOT EXISTS`) bundle, which either succeeds or fails loudly on a colliding pre-existing table — the failure mode the design doc (§2 "Open path") called out. Two new in-crate tests in `schema.rs`: `ensure_schema_refuses_unknown_user_version` exercises the `other => Err(Internal(_))` arm of the version gate (previously uncovered), and `ensure_schema_rolls_back_on_mid_bundle_failure` pre-seeds a colliding `rooms` table on a fresh file, opens the store, and asserts that the bundle's transaction rolls back leaving `user_version = 0` and the pre-existing table intact.

(c) Knock rooms are emitted under `rooms.knock` (beyond the design doc's join/invite/leave-only enumeration) because the upstream `candidate_rooms` includes `Membership::Knock` (`sliding_sync/build.rs:292,311`) and skipping them would silently drop rooms the v5 handler chose to return. `knock_state.events` is built by manually stripping each `Raw<AnySyncStateEvent>` from v5's `required_state` down to `{type, state_key, sender, content}` — ruma 0.15 has no `JsonCastable` impl from the type-erased `AnySyncStateEvent` enum to `AnyStrippedStateEvent`, and no general `fn strip()`; `Raw::cast_unchecked` would emit the full event JSON under a stripped type label (soft lie) so manual reshape in `translate::strip_state_event` is the honest path. (d) Conn registry uses `conn_id = "__legacy__"` so legacy and real sliding-sync sessions never collide on `(user_id, conn_id)`. (e) `parse_legacy_query` maps empty `since=` to None (initial-sync semantics matching Synapse); `is_truthy` accepts only `"true"` case-insensitively (Synapse-style permissive `"1"`/`"yes"` parsing deferred). (f) Unknown-membership rooms in `translate_response` probe `room.invite_state.is_some()` as a race-tiebreaker before defaulting to the `join` bucket — handles the narrow window where a fresh invite arrives between `rooms_with_membership` snapshot and the v5 handler emitting it. (g) `prev_batch` is the empty string for joined/leave rooms (no `/messages` impl yet — the token is never redeemed); per-room `summary` / `unread_notifications` intentionally omitted (out of scope, matches the doc). (h) The handler `legacy_sync::handle` mirrors the sliding-sync wrapper's state-extraction (`lock_app` scoped to a block so the std-mutex guard drops before any `.await`) and error mapping (`UnknownPos` → 400 M_UNKNOWN_POS, `BadRequest` → 400 M_INVALID_PARAM, `Storage` → 500 M_UNKNOWN). `fetch_memberships` snapshots `StateStore::rooms_with_membership` for all five `Membership` variants *before* the v5 call so bucketing reflects the same point-in-time the v5 response observes. Not in scope (deferred per `docs/legacy-sync-stub.md`): `creation_content` merge in `create_room`, `device_id` echo in `post_login`, `GET /rooms/{id}/state/{type}/{key}`, rejecting non-v12 `room_version` (the doc's "three cheap-win fixes").
